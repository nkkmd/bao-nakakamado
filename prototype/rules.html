Bao Nakakamado・NYAKUAの考案者：nkkmd／初公開日：2026年9月30日。 考案・公開・変更履歴を参照してください。

Bao Nakakamadoは、Bao la Kiswahiliをベースに独自ルールNYAKUAを採用したオリジナルのBaoです。盤・種まき・捕獲の仕組みを受け継ぎ、ハンドのKETEを使った駆け引きを加えています。v0.9.0で案A「着手終了後の終点2個追加」を正式採用し、v0.10.0では原型Bao la Kiswahiliで正式採用された takasia を基礎規則として追加しました。NYAKUA案Aは維持します。

1. 勝利条件

次のどちらかを達成すると勝ちです。

  • 相手の前列8穴をすべて空にする。捕獲の途中でも直ちに終局します。
  • 相手の手番に合法手をなくす。

後列にKETEが残っていても、前列が全空なら敗北します。着手処理後に自分の前列が全空になった場合も負けです。KETEの合計数による得点勝負ではありません。ハンドが0になったこと自体は敗北ではありません。

2. 盤・用語・初期配置

各人が前列8穴と後列8穴を使い、両者合計4列32穴です。穴番号は各人から見て左から1〜8。相手と向き合う側が前列です。

用語意味
KETE（ケテ）石・種。両者合計64個
通常ハンド初期22個からまだ盤へ投入していない手元のKETE。相手のNYAKUAで減ることがある
NAMUA（ナムア）ハンドを使う段階。NYAKUAが作用する
MTAJI（ムタジ）両者のハンドがともに空になり、盤上だけで指す段階。takasiaが作用する
takata（タカタ）一着手を通じて捕獲しない手
連続種まき / relay sowing終点のKETEを持ち上げ、同じ着手を続けること
NYUMBA（ニュンバ）自分の前列5番にある特別な穴
kichwa（キチュワ）前列の両端1番・8番。捕獲したKETEの入口
kimbi（キンビ）前列2番・7番。捕獲時の入口に制約がある穴
NYAKUA（ニャクア）NAMUAの連続捕獲後、条件を満たせば両ハンドから終点へ2個追加する独自規則
takasia（タカシア）MTAJIのtakata後に成立し得る、相手の次の1手だけ特定の前列穴を制約する基礎規則

各人の初期配置は次のとおりです。

自分から見た穴番号12345：NYUMBA678
前列00006220
後列00000000

各人の盤上10個、ハンド22個、計32個です。両者ともNYUMBAを所有した状態で、SOUTHが先手、NORTHが後手。NAMUAから交互に指します。

画面ではSOUTHの前列をSF1〜SF8、後列をSB1〜SB8、NORTHをNF/NBで表示します。NORTHの番号は画面では反転します。真向かいの前列穴は本人視点番号の合計が9です。SF5の真向かいはNF4で、両者のNYUMBAは真正面ではありません。

3. 前列・後列を循環する種まき

種まきは自分の前列と後列の16穴だけを使います。相手の穴へ蒔きません。前列の端の次は、後列の同じ側の端へ進みます。

方向経路の例
前列を右へ…F6 → F7 → F8 → B8 → B7 → … → B1 → F1 → F2…
前列を左へ…F3 → F2 → F1 → B1 → B2 → … → B8 → F8 → F7…

穴から持ち上げたKETEは開始穴の次の穴から1個ずつ蒔きます。捕獲したKETEは指定された前列入口の穴そのものへ最初の1個を置き、その後は内側へ進みます。

ひとまとまりの種まきが終わるたび、最後の1個を置いた穴で判定します。

  1. 最後の1個を置く直前に空だった穴なら、1個を残して着手終了。
  2. 空ではなかった穴なら、捕獲手ではまず捕獲できるかを確認。
  3. 捕獲しない場合、NAMUAのNYUMBA停止規則を確認。
  4. 止まらなければ終点のKETEを持ち上げ、同じ方向へ連続種まき。

途中で通過した穴では判定しません。一着手中に何回続いても、途中で相手の手番にはなりません。takataで始めた手は、その着手全体を通じて捕獲しません。takasiaが有効なMTAJI手だけは、第9章のとおり対象穴での開始と終点処理に追加制約があります。

4. NAMUA：ハンドを使う段階

捕獲手

自分の前列で、KETEがあり、真向かいの相手前列にもKETEがある穴を探します。1つでもあれば、必ずそのいずれかで捕獲します。

  1. 合法な自分の前列穴へ自分のハンドから1個を投入。
  2. 真向かいの相手前列穴のKETEをすべて取る。
  3. 捕獲したKETEを指定された自分の前列入口から蒔く。
  4. 終点に応じて、さらに捕獲・連続種まきを続ける。

開始穴に元からあったKETEと投入分はその穴に残し、捕獲したKETEとは一緒に持ち上げません。NYUMBAも、条件を満たせば捕獲の開始穴にできます。

捕獲手がなければtakata

合法な前列の開始穴へ自分のハンドから1個を投入し、投入後の中身を持ち上げ、左右いずれかへ蒔きます。後列からは開始しません。NYUMBAの2個蒔きは例外です。

  • 空穴からは開始できません。通常は2個以上ある前列穴を使います。
  • NYUMBAを所有していれば1個の穴も選べます。所有していなくても、通常の開始候補に2個以上の穴がなければ1個の穴を選べます。
  • 所有中で6個以上のNYUMBAは通常のtakata開始穴にできません。前列で所有中NYUMBAだけにKETEがある場合は、第7章の2個蒔きです。
  • 自分の前列を空にする禁止手は選べません。合法な候補は画面で光ります。

5. 捕獲の入口と連続捕獲

捕獲するのは相手の前列です。後列やハンドを通常の盤上捕獲で取りません。NYAKUAによるハンド奪取は第6章の別処理です。

自分の捕獲穴NAMUAの最初の捕獲同じ着手の後続捕獲・MTAJI
前列1・2番左入口（前列1番）左入口
前列3〜6番左か右を選ぶ前列を右へ進む方向なら左入口、左へ進む方向なら右入口
前列7・8番右入口（前列8番）右入口

種まきの終点が自分の前列で、最後の1個を置く直前に空ではなく、真向かいの相手前列にKETEがあれば、捕獲手ではさらに全捕獲します。後列を終点とする場合は捕獲せず、通常の連続種まき判定をします。

相手前列が全空になった時点で終局し、最後に取ったKETEを蒔き直しません。棋譜内部ではその分を保留数として記録し、総数を保存します。

6. NYAKUA：着手終了後の終点2個追加

NAMUAで開始した一手の通常処理を完了してから、次のすべてを満たせば追加します。

  • 同じ着手の捕獲回数が2回以上。捕獲した石数ではなく、捕獲した穴の回数です。
  • 通常の1個投入・捕獲・種まきが終わった時点で、自分のハンドに1個以上、相手に2個以上ある。
  • 両者の前列が空にならず、即時終局や連続種まきの安全停止をしていない。
  1. 自分と相手のハンドから各1個を取り、蒔き終わりの自分の穴へ計2個を置く。
  2. 終点を再判定せず、捕獲・種まきを再開しない。
  3. 両ハンドが0ならMTAJIへ移り、次の手番へ進む。合法手なしによる勝敗は追加後の盤面で判定する。

3回以上捕獲しても一手につき一度だけです。終点が後列や所有中NYUMBAでの停止穴でも追加します。追加でNYUMBAの所有は回復しません。相手の最後の1個は奪いません。自分の最後の1個は追加に使えますが、開始時の通常投入後に0なら発動しません。

例：手番開始時に自分6個・相手2個なら、通常1個投入で自分5個。2回以上捕獲して通常処理を完了すると自分4個・相手1個になり、終点に2個追加します。開始時の自分1個は通常投入で0になるため、追加しません。

別確保・次手3個投入・追加手番はありません。 片方のハンドだけから2個使う、不足分だけ追加する、次手へ繰り越す処理もしません。MTAJIではNYAKUAを使いません。

両ハンド0への移行は、その着手のNAMUA処理と追加を終えてからです。通常初期局面からのハンド枯渇パスは生じません。人工局面を扱う互換用パスは保持します。正常に着手が完了する限りNAMUAは44手以内に終わります。一着手内やMTAJIの停止証明ではありません。

7. NYUMBA

自分の前列5番はNYUMBAです。穴の位置と所有状態を区別します。

NAMUAの種まきが、所有中で6個以上あるNYUMBAを終点とした場合：

状況処理
takata停止
捕獲手で真向かいから捕獲できる捕獲を優先し、停止不可
捕獲手で真向かいが空「止める」か「使う」を選択

「止める」は所有を保って着手終了。「使う」は中身を持ち上げ、同じ方向へ蒔き、所有を失います。所有中でも6個未満なら上記の停止機能は働きません。相手にNYUMBAの全KETEを取られた場合や、穴を空にする処理でも所有を失います。一度失った所有は、KETEが増えても戻りません。

NAMUAで捕獲手がなく、前列で所有中NYUMBAだけにKETEがある場合、ハンドを1個投入後に2個だけ持ち上げて左右へ蒔きます。例えばNYUMBA6個なら7個から2個を蒔き、5個残します。

MTAJIではNYUMBAを通常の穴として扱い、特別な停止・2個蒔きは使いません。

8. MTAJI：前列・後列の盤上で指す

ハンドからは投入せず、NYAKUAもハンドの投入もありません。

捕獲手は、前列または後列の2〜15個の穴から全数を蒔き、終点が自分の前列で既にKETEがあり、真向かいの相手前列にもKETEがある手です。捕獲手があれば必ず選びます。最初の種まき後に全捕獲し、連続処理を続けます。

捕獲手がなければtakataです。前列に2個以上の開始候補があれば前列から、なければ後列の2個以上の穴から始めます。開始穴の全数を左右へ蒔き、その着手では捕獲しません。自分の前列を空にする禁止手は選べません。

16個以上の穴は捕獲手の開始には使えませんが、takataには使えます。0〜1個の穴からはMTAJIの着手を開始できません。後列に動かせる穴があっても、前列全空による敗北が優先されます。

9. takasia

takasia は MTAJI の takata が正常に終了した後に成立を判定します。直前に指した側を攻撃側、その相手を防御側とします。

次の条件をすべて満たす場合、防御側の次の1手だけ特定の前列穴をtakasia対象にします。

  1. 防御側には、最初の蒔きで成立する捕獲手がない。
  2. 同じ盤面で攻撃側がもう一度指すと仮定したとき、最初の蒔きで捕獲対象となる相手前列穴が、重複を除いてちょうど1穴だけである。
  3. その穴が以下の例外に該当しない。

対象外となる穴

  • KETEが1個だけの穴。
  • 防御側前列の唯一の占有穴。
  • 防御側前列で唯一2個以上ある穴。
  • 防御側が所有中のNYUMBA。

所有を失ったNYUMBA位置は通常穴として判定します。

次の1手での作用

  • 対象穴からtakataを開始できません。
  • 種まき途中で対象穴を通過する場合は、通常どおり1個を置いて続行します。
  • 最後の1個が対象穴へ入った場合は、到達後のKETE数にかかわらず、そこで連続種まきを停止します。
  • 制約は防御側がその1手を終えた時点で失効します。
  • その手自身が新しいtakasia成立条件を満たした場合は、古い制約を消費したうえで、反対側の次の1手に新しい対象を設定します。

NAMUAからMTAJIへ移行しただけではtakasiaは成立しません。MTAJIの捕獲手の終了後や終局後にも新規成立させません。

10. 画面・棋譜・実装範囲

2人対戦・簡易コンピューター対戦を選べます。光る穴を選び、方向・入口・NYUMBAの選択肢を選んでください。高速再生・サウンド・棋譜JSON保存に対応します。簡易コンピューターは現行v0.10.0の合法手と遷移を使い、takasia対象穴からの開始禁止・対象穴での停止も同じエンジンで処理します。旧v0.8.0の学習済みモデルと探索Workerは現行画面で使用しません。探索コンピューターは後続工程です。

棋譜はformat bao-nakakamado-prototype、version 9、rulesVersion: "0.10.0"、baseRulesVersion: "0.2.0"、baseRulesRevision: "BAO-RULES-V0.2.0-TAKASIA-001"、variantRule: "takasia-namua-end-pit-two-protect-last-two-row-ring-hand22"、publicAdopted: true、takasia: true。旧v0.9.0のversion 8以前は、このルールの棋譜として読み込みません。

placedは手の開始時の投入数、capturesは捕獲回数、stolenは相手ハンドから取った数、addedは終点への追加数（0か2）、ownAdded・opponentAddedは各ハンドから追加した数、endpointは追加先（非発動ならnull）。各着手にはtakasiaBeforeとtakasiaAfterも保存します。通常ハンドはreserve、互換用nyakuaReserveは常に[0,0]、終局時の捕獲保留数はpendingです。画面での棋譜読み込みは未実装です。

MTAJI循環は共通エンジンの既知の制約です。連続種まき512回の安全上限で停止し、画面とadjudication: "safety-stop"で通常勝敗と区別します。再現用final.winnerはエンジン内部値を保持しますが、裁定結果のoutcome.winnerはnullです。循環禁止手・引き分けなどの新裁定は導入していません。

先後均衡や初期局面の必勝は未確定です。試験コードの一致は全局面の停止・均衡の証明ではありません。

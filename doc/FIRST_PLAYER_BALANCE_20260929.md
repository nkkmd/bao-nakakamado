## 問いと結論

NAMUA中の一手で2回以上捕獲すると相手のハンドからKETEを1個奪う試作ルールについて、先攻・後攻に明確な差が出るかを調べた。また、片側のハンドが空になった場合にパスさせる現行方式と、その側だけ次の自分の手番からMTAJIへ入る案を比較した。

初期配置と処理を南北反転しても勝敗は完全に反転し、SOUTH/NORTHという席の固有の差は確認されなかった。一方、先攻勝率は手選び方針で45.1～61.7%に変わり、現時点で先後均衡を確認できない。個別MTAJI案はパスを解消し、先にハンドが空になった側の勝つ余地を増やしたが、先後差の一貫した改善は示さなかった。いずれの方式も未採用の変更として扱い、調査時点の製品コードは現行パス方式のままだった。

## 比較条件

- 初期局面は試作 v0.4 の `prototype/engine.js`。両者に同じ手選び方針を適用する。最初に指す側をSOUTHとした1,000局（応手評価のみ300局）を表に示す。同じseedでNORTHから開始する反転試験も実施したが、これは独立した局数に加算しない。
- 現行方式はエンジンの全体で共有するNAMUA/MTAJIを使用。片側のハンドが0ならパスし、両者が0になるとMTAJIへ移る。
- 個別MTAJI案は、ハンドが0になった側が次の自分の手番からMTAJIの合法手を使い、相手はハンドが残る間NAMUAを続ける。着手途中では切り替えない。MTAJI側の捕獲では[NYAKUA（ニャクア、ハンド奪取）](TERMINOLOGY.md)を行わない。MTAJIの合法手がなければ `no-move` 敗北とする。元エンジンの次手番判定を、奪取後のハンド残数とその側の段階に合わせて再評価する仮の実装であり、製品仕様の確定ではない。
- ハンド奪取は試作の `steal.js` と同じく、NAMUAの一手で捕獲イベント2回以上、相手のハンドにKETEが残る場合に1個。終局した着手にも適用する。
- 一手評価の値は、終局勝敗を優先したうえで `2 × 前列KETE差 ＋（盤上とハンドの全KETE差）`、捕獲手に2点を加える。無作為は候補手から一様選択、「簡易評価＋揺らぎ」は最高値との差が7点以内の手から一様選択、「一手評価」は最高値の手から一様選択。「応手評価」は相手の各応手後に得られる評価の最小値が最大になる手を選ぶ。これは試作用の簡易方針であり、AI-GEN4ではない。
- 各方針で同じ1,000個（応手評価は300個）のseedを両方式に使った。擬似乱数はxorshift32、初期seedは32ビット演算で `0x924f3aa1 + i × 0x9e3779b1`（`i = 0..N-1`）。一局400手で打ち切る設定だが、以下の対局に未終局はない。

前回の[段階移行候補の探索](HAND_EXHAUSTION_PHASE_CANDIDATE.md#探索的な比較)とは手選び、評価式、seed、手数上限が異なるため、勝率や局数を合算しない。

## 先攻勝率

| 手選び | 局数（各方式） | 現行パス | 個別MTAJI | 勝者が変わった対局 |
| --- | ---: | ---: | ---: | ---: |
| 無作為 | 1,000 | 479 / 1,000（47.9%） | 494 / 1,000（49.4%） | 185（個別案で先攻勝ちへ100、後攻勝ちへ85） |
| 簡易評価＋揺らぎ | 1,000 | 468 / 1,000（46.8%） | 471 / 1,000（47.1%） | 79（先攻へ41、後攻へ38） |
| 一手評価 | 1,000 | 451 / 1,000（45.1%） | 446 / 1,000（44.6%） | 77（先攻へ36、後攻へ41） |
| 応手評価 | 300 | 185 / 300（61.7%） | 185 / 300（61.7%） | 0 |

応手評価の300局はハンド奪取が一度も起きず、両方式で同じ対局となった。これはその簡易方針の挙動であり、熟練者が奪取を避けることの証明ではない。SOUTH/NORTHを反転した試験では各条件の勝敗数も反転した。したがって盤面の上下による固定的な差は見られないが、手番順の有利不利については方針を変えると結論の向きも変わる。

## 対局の進行とハンド枯渇

次表はハンド奪取を有効にした1,000局ずつの比較。`先に枯渇した側の勝ち` の分母は、両者のハンドが空になる前にどちらか一方が先に0になった対局数。`早期MTAJI` は、相手がまだNAMUAの間にMTAJIの着手を実際に行った対局数。

| 手選び | 方式 | 先に枯渇した側の勝ち | 早期MTAJI | `no-move` 終局 | 平均手数 |
| --- | --- | ---: | ---: | ---: | ---: |
| 無作為 | 現行パス | 70 / 739（9.5%） | 0 | 30 | 41.7 |
| 同上 | 個別MTAJI | 203 / 739（27.5%） | 649 | 120 | 48.7 |
| 簡易評価＋揺らぎ | 現行パス | 17 / 545（3.1%） | 0 | 7 | 34.4 |
| 同上 | 個別MTAJI | 88 / 545（16.1%） | 472 | 83 | 37.2 |
| 一手評価 | 現行パス | 23 / 584（3.9%） | 0 | 28 | 35.2 |
| 同上 | 個別MTAJI | 90 / 584（15.4%） | 510 | 218 | 38.2 |

現行方式ではハンドが空になった側にパスが発生した。個別案ではパスが0になり、先に枯渇した側の勝ちが増えた。ただし `no-move` 敗北も増え、対局は平均で長くなった。勝率表と併せて見ると、先後差だけで採否を決める根拠にはならない。

## 再現方法と検証範囲

Node.jsでリポジトリのルートから実行する。標準出力は条件ごとのJSON行であり、上表の「勝者が変わった対局」は `paired` モードで確認する。

```sh
node tools/first-player-balance.cjs 1000 random,noisy,greedy shared,mixed
node tools/first-player-balance.cjs 1000 random,noisy,greedy paired
node tools/first-player-balance.cjs 300 reply shared,mixed
node tools/first-player-balance.cjs 300 reply paired
```

ハンド奪取を無効にした対照試験では、各手選び1,000局において現行方式と個別案の勝敗、平均手数、終局理由が一致した。ハンド差がないときに仮の段階移行処理だけで結果が変わっていないことを確認した。また各条件で開始側をNORTHへ反転すると、結果のSOUTH/NORTH表示が完全に入れ替わった。これらは仮実装の整合確認であり、混合段階の全局面を網羅するものではない。

着手方針は単純で相互依存のある一連の対局を生成する。seedを変えた対局数を人間同士や強いAIの独立な勝率標本とみなさず、統計的な優劣や最善プレイのゲーム理論値は主張しない。個別MTAJIの合法手・nyumba・終局境界を仕様化してテストし、複数の強さと開局条件で先後を入れ替えた比較、および人間同士の対局を経て採否を判断する。

# NYAKUAで相手の最後の1個を保護する条件の採用・進行確認

2026年10月1日。変更前の基準は `2321e0caec0784f6aebd84f2e0248d9ba5cd976e`。ユーザーの指示により、進行確認後に試作v0.6.1へ暫定採用する。初期ハンド12個、盤上各人10個、各人1列8穴、折り返し、NYUMBA6個基準を維持する。

## 結論と適用範囲

NYAKUAはNAMUAの一着手で2回以上捕獲し、相手のハンドが2個以上のときに1個だけ移す。相手のハンドが0〜1個なら、盤上の捕獲・種まきは通常どおり行い、ハンドからは奪わない。終局した着手の記録にも同じ条件を適用する。

新旧各4,000対局がすべて通常終局し、今回の確認では進行に大きな支障は見つからなかった。最後の1個保護を暫定採用する。先後均衡の達成や最善プレイでの勝率を証明した結果ではない。初期条件の他の改善候補は今回採用しない。

## 進行上の変化

本人による最後の1個の投入は可能である。その手でNYAKUAが起きて自分のハンドへ1個戻れば、ハンドは0にならない。戻らずハンド0になり、終局しなければ、次の相手が残数を一穴へ投入する。両者0なら共通MTAJIへ移行する。

通常の初期局面から、NYAKUAで次の手番の相手をハンド0にすることはできなくなる。このため、ハンド0側へ手番が回るパスは生じない。手番開始時に片側0の入力局面を扱う既存のパス処理は保持し、人工局面の回帰テストで確認する。これは通常の対局からパスへ到達するという主張ではない。

NYAKUAはハンド間の移動だけであり、両者のハンド合計を増やさない。各NAMUA着手で1個以上投入し、通常の初期局面からパスも起こらないので、初期ハンド合計24個は最大24手番で使い切る。ただし、一着手内の連続種まきや、MTAJI全局面の停止の証明とは別である。

## 試験条件と結果

Node.js v24.19.0、外部ライブラリなし。同じ初期条件・方針・seed範囲で旧条件と新条件を比較する。seed indexは1000〜1999、各方針・各条件1,000局、計8,000局。方針は無作為 `random`、評価差7以内の `noisy`、一手評価 `greedy`、相手の一手応答を評価する `reply`。最大400手番で未終局ならエラーとする。途中の安全上限 `relay-limit` 到達もエラーとする。

すべて `front-empty` または `no-move` で終局し、未終局・安全上限到達・KETE総数違反・負数・合法手なしの非終局局面は0件だった。新条件の最長対局は41手番。平均の増加は約0.06〜0.55手番だった。

| 方針 | 旧平均手番 | 新平均手番 | 全投入あり：旧 → 新 | MTAJI着手あり：旧 → 新 | パスあり：旧 → 新 | 先手勝率：旧 → 新 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| random | 17.689 | 18.160 | 396 → 333 | 293 → 358 | 200 → 0 | 49.5% → 50.6% |
| noisy | 11.669 | 11.743 | 96 → 60 | 31 → 42 | 56 → 0 | 43.7% → 44.1% |
| greedy | 11.812 | 11.876 | 92 → 57 | 24 → 37 | 59 → 0 | 46.0% → 46.4% |
| reply | 20.254 | 20.806 | 520 → 460 | 400 → 596 | 247 → 0 | 52.4% → 53.0% |

全投入は減る方針もあるが、各方針で残る。MTAJIの実際の着手も各方針で確認した。先手勝率は固定方針での観測値であり、先後有利不利の解消を示さない。強い探索方針、人間同士の操作感、他の初期ハンド条件は本試験の対象外。

## 個別の検証

- 25件の自動テストが通過。相手ハンド1個では3回捕獲しても奪わず、2個では1個奪って1個残す到達可能な局面を確認した。0個・捕獲1回・MTAJIの非発動、通常の捕獲、NYUMBA選択、一穴全投入、旧4列盤のテストも維持した。
- 到達局面からの候補手10,451件で、イベント版と通常版、最後のスナップショット、入力不変を照合した。最後の1個を奪う旧処理だけを差し引けば新処理と一致し、保護の対象候補145件を確認した。
- 新条件で座席交換200局の最終盤面・勝者・手番数が対称になり、棋譜再構築200局の最終盤面が一致した。座席交換は8,000局の主集計には加えない。
- 画面の自動テストで16穴、ハンド表示、7個の一穴全投入の再生、棋譜保存、コンピューターの手番、再生取消・対局再開始を確認した。実ブラウザーでの視覚確認や人間の操作感の検証は行っていない。
- 旧条件の比較コードの379候補手・40選択が一致。旧ハンド6個の保存済み必勝証明は両座席で各514局面・519辺・555応手を再検証し、不正な証明3件の拒否も確認した。旧証明の結論を新条件へ適用しない。

## 実装と棋譜

`prototype/steal.js` は現行の `bounce-engine.js` が持つ `NYAKUA_PROTECT_LAST: true` を読み、発動条件に最後の1個保護を適用する。旧エンジンの既定条件と、歴史的な1列盤の試験で明示する `createForEngine(E, { protectLast: false })` は旧条件を再現する。

画面の表記とキャッシュ識別子をv0.6.1へ更新する。棋譜JSONは `version: 5`、`rulesVersion: "0.6.1"`、`nyakuaProtectLast: true`、`variantRule: "namua-steal-one-protect-last-fixed-pit-bulk-one-row-bounce-hand12"`。各手の `placed`・`captures`・`stolen` を維持する。旧v0.6.0とはルールが異なり、その棋譜を現行条件で同一結果に再現することは保証しない。画面の棋譜読み込みは未実装。

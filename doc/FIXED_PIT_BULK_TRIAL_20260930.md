## 挙動

NAMUAで相手のハンドが0、自分のハンドが2個以上の手番では、従来の合法手から穴・方向を一度選ぶ。通常の1個投入を、自分のハンドの全KETEを**選んだ一穴へ一度に置く処理**へ置き換える。その後は同じ着手の捕獲またはtakata、連続種まき、nyumba、終局を元のエンジンどおり処理する。各穴へ順に分配せず、複数の手に分けない。進行表示も一括投入を一段階で表示する。

自分のハンドが1個、相手のハンドが残る、またはMTAJIでは従来の着手。自分のハンドが0なら両者のハンドが0になるまでNAMUAでパスし、両者0になれば従来のMTAJIへ移る。[NYAKUA（ニャクア、ハンド奪取）](TERMINOLOGY.md)も残すが、相手が0の投入中には奪えない。全投入後の捕獲で相手の合法手がなくなれば従来の `no-move` で終局する。

`prototype/engine.js` は取り込んだ元エンジンのまま。画面は `prototype/bulk-engine.js` を使用し、NAMUA投入だけを変える。研究ツールが参照する元エンジンを保存して再現性を保つ。`prototype/steal.js` は棋譜に投入数 `placed` を記録し、再生時に照合する。ダウンロード形式は `version: 3`。v0.4の `version: 2` は別ルールの記録として扱う。

## 自動確認

```sh
node --test prototype/steal.test.js prototype/app.test.cjs tools/fixed-pit-bulk-study.test.cjs tools/fixed-pit-triggered-study.test.cjs
```

到達可能な局面で、6個の一括投入と直後の捕獲・即時 `no-move`、takata、nyumba選択、1個だけの通常投入、投入を一画面で示す動作、ハンド奪取、KETE総数、棋譜の再構築を確認した。6個の捕獲手と3個のtakata手では、元のエンジンが1個を投入する直前に残り分を同じ穴へ置いた局面を作り、投入直後の局面と**それ以降の全イベント・終局面が一致**することを確認した。試用エンジンと先行のメモリ上の研究実装を50局の完全対局で一着手ずつ比較した。既存研究ツールのテストも通過した。実ブラウザーでの見た目・操作確認と人間対局は残る。

[先行調査](FIXED_PIT_BULK_STUDY_20260930.md)では無作為や簡易評価の条件でハンド枯渇側の勝ちと `no-move` がともに増え、平均手数は短縮しなかった。先後差の明白な解消や発生を示す試験ではない。人間の納得感も未測定。

## 人間対局で見る点

- ハンドが空になる前の段階で、次に相手が一穴へ全投入することを予測できるか。
- 全投入の個数、選ばれた穴、捕獲と連続種まきの続き、終局理由を表示だけで追えるか。
- 空ハンド側のパスが続く場面や、全投入直後・後続MTAJIの `no-move` を公平と感じるか。
- 穴・方向を変えれば結果を避けられる局面を本人が理解できるか。
- 先後を入れ替え、全投入前の残数が少数と多数、捕獲とtakata、即時終局と継続の例を比べる。

この試用の結果を受けて[暫定順位](HAND_EXHAUSTION_OPTIONS_REVIEW_20260930.md)を再検討する。

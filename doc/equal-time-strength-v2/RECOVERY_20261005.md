# 同時間正式比較v2：原記録の読取り専用集約手順

2026年10月5日（日本時間）。説明文はCC BY-SA 4.0、監査コードとJSONはMIT。ルールv0.8.0・棋譜7、考案者nkkmd、初公開2026-09-30 JSTを維持する。

初回run 37307084139は20shard・160組320局をCOMPLETEとして封印し、残り12shardは未登録CPUを探索前に拒否した。完成20shardのZIP digest・Actions origin・永続session／lease／seal・全棋譜の再生を監査済み。途中の勝率・強度・棋力指標は算出していない。

固定workerはCOMPLETEのコピーより先に現在hostのruntimeを確認する。このためresumeで完成shardのcarrier artifactが作成されない場合もある。これは元のCOMPLETE記録の欠損を意味しない。現行workflowのcurrent-run-only集約はそのrunのartifactが32個揃わなければHOLDとなる。workflow成功やcurrent-run集約の成功へ読み替えない。

以下を、全固定対局の結果を集計する前に定める追加の読取り専用監査経路とする。固定contract・worker・探索・モデル・CPU許可一覧・主要判定・局数を変更しない。

1. shardごとに最初の実測がCOMPLETE・activeなし・pendingなしとして封印された原artifactを固定する。origin（repository／run／attempt 1／mainのhead SHA）、artifact ID／name／digest／bytes数、同一session、lease／sealを記録する。完成shardの後続carrierを原実測に差し替えない。
2. 完成原receiptの集合は単調に追加する。新しいmanual resumeには全完成receiptを指定し、未着手shardだけを実測する。未登録hostでleaseが作られず探索前に止まったshardは未着手として扱う。leaseあり／sealなし／activeありのshardはHOLDとし、自動で再測定しない。
3. 正確なActions metadataと原ZIPを取得し、既存の安全展開と変更していない `auditDirectory` により全JSONのchecksum、原タグ、固定環境、担当順序、通常遷移と探索遷移による全棋譜を照合する。読取り専用監査hostで探索や環境偽装をしない。
4. 全32shard・256組512局がCOMPLETEとして揃った場合だけ、変更していない `aggregate` を一度適用する。同一session・shardの完全被覆・unique開幕・全固定判定を既存実装で再確認する。部分結果の棋力集計をしない。
5. exact原ZIP32個、原receipt32個、session、既存aggregateの原reportを結果専用の新しいimmutable branchへ保存する。複数runから原記録を集約した事実、各current-run集約の状態、この追加経路による全件監査を別の実行記録へ明記する。同名結果refの異なるbytesを上書きしない。

`audit-public-records.cjs` はmetadata.jsonと原ZIPを入力に既存worker exportsを呼ぶ読取り専用入口である。metadataはGitHubから取得した原run・artifact・ref・annotated tagの値を保存する。実行例：`node doc/equal-time-strength-runs/audit-public-records.cjs PATH_TO_PINNED_RECORDS`。この経路は未完成・中断対局の回復ではなく、完成・封印済み原記録の保存と監査に限る。正式finalや収集鍵へアクセスしない。結果がHOLDでも固定条件のまま保存し、再選定・再測定に利用しない。公開AIの採用・画面接続・moto g52j 5G実機試験は別工程である。

# v0.8.0の先攻・後攻の有利不利：詳細調査

調査日：2026年10月3日（日本時間）。調査ID：V080-BALANCE-20261003-R2。

## 判断の要点

基本評価で相手の応答や数手先を読む自己対戦では、先攻有利の傾向を確認した。先攻勝率はreplyで60.6%、3手先76.1%、4手先57.2%、5手先56.8%、6手先57.8%。10種類の自己対戦をまとめてHolm法で多重比較を補正しても、この5条件の差は残った。

一方、無作為・近い評価の手から選ぶ方針はともに50.1%。合法手数と前列の占有穴数も評価する4手先は52.4%、6手先は49.0%で、50%との差を確認できなかった。後者の95%区間は44.1–53.9%であり、実用上無視できる差に収まるという同等性まで確認したものではない。

**現行v0.8.0の先後均衡は未確認。基本評価の探索では先攻寄りだが、方針に共通する固定的な先攻優勢や後攻優勢は確定していない。** 3手先の76.1%をゲーム全体や熟練者対戦の勝率に置き換えない。現時点では規則を維持し、先攻・後攻の一方だけハンドを増減する調整は保留するのが妥当と考える。

正式対局は19,600局、通常終局19,598局、安全上限停止2局、パス0件。停止2局は自己対戦search4と初手固定open-search4に各1局で、勝敗から除外した。初回の相関した乱数による19,600局・準備試験・画面AIの固定棋譜を正式対局数に加えていない。

正式実行：[Actions 37113643263](https://github.com/nkkmd/bao-nakakamado/actions/runs/37113643263)。対局実行commit：`faa782565d5a95f384c0a32a8d279cd8edae2205`、Node v24.19.0。全17タスク・検証・集計が成功した。製品コード、初期ハンド、規則を変更していない。

対象は現行の `prototype/next-turn-engine.js` と `prototype/steal.js`。4列32穴、ハンド22個ずつ、NYAKUAの最後の1個保護、別確保分の次手3個投入、共通MTAJI、512回安全上限を使用した。初期配置と製品コードを変更していない。

正式対局は計19,600局。旧試験と今回の準備試験はこの対局数に加えない。全局の全着手で総KETE64個と非負整数を検査した。

Aが先攻・Bが後攻の対局と、Bが先攻・Aが後攻の対局を同じseedで組にした。乱数列は方針主体に付けて交換する。組の平均得点（0、0.5、1）を単位に標準誤差で区間を計算。通常終局していない対局が含まれる組はこの区間から除外し、未決着の数は元集計に残す。

最終の組はsearch6-mobilityが先攻250局・後攻250局すべてに勝った。このため各組の先攻得点が必ず0.5になり、元の標準誤差区間は50.0–50.0%へ縮んだ。これを母集団での完全な均衡や高い精度の証拠として扱わない。上の表では、この条件だけ分散0でも幅を持つHoeffdingの保守的95%区間を示した。他の3組の区間は組単位の標準誤差による近似。全4組の保守区間と元の区間は[統計補記](../tools/v080-balance/results/statistical-diagnostic.json)に保存し、元の集約数値は変更していない。

保守区間は組得点を0〜1とし、半幅を `sqrt(log(2/0.05)/(2×組数))` とする。独立したseedの組という確率的モデルを仮定する。先後交換の50%には、強い方針が両方の手番で勝つことで先後差が隠れる場合が含まれる。

## 解釈・検証・保存

勝率の分母は通常終局局数。512回安全上限・同一局面反復・400手打切りは未決着として勝敗から除外する。全試験局を分母にして未決着を先攻敗／先攻勝に置いた上下限をJSONに保存。手数平均は打切りまでを含む。

各方針・条件は異なるseed集合。自己対戦の区間はWilson法。区間は指定された確率的方針と初期局面での変動を示し、ゲーム全体や人間の母集団の区間ではない。探索方針には同じ局面・同じ棋譜へ収束する性質があるため、独立seedでも多様な対局を意味しない。異なる条件の総対局数を合算して単一の勝率や独立標本区間を出さない。複数条件を比較しているため、50%を外れた区間だけで普遍的な先後差を主張しない。

GitHub Actionsで実行。20局／20組ごとに原子的チェックポイントを保存し、コードSHA-256と条件署名を検査する。失敗時もartifact保存を試みる。再実行時は同じ署名の完了ブロックを復元すると再開できる。全taskの集計・ソース・署名を照合し、各taskの先頭・中央・末尾と全未決着局を再実行、代表棋譜を現行の棋譜再生関数で再構築した。南北交換でも全着手の一致を確認した。検証数は `verification.json` を参照。

[実行方法](../tools/v080-balance/README.md)、[集約結果](../tools/v080-balance/results/summary.json)、[検証結果](../tools/v080-balance/results/verification.json)、[対局単位の原記録](../tools/v080-balance/results/checkpoints.json.gz)。原記録はJSONファイル名→内容のgzipアーカイブで、展開後に同じ検証を実行できる。

## 追加の統計整理と方法点検

10種類の自己対戦に対し、先攻勝率50%を帰無仮説とする両側の正確二項検定を行い、Holm法で10条件の多重比較を補正した。reply、search3、search4、search5、search6で先攻寄りの差が残った。greedyの後攻寄りは通常の95%区間では50%を外れるが、補正後p=0.0618で確認基準に達しない。他の4条件も差を確認していない。正確p値5条件をSciPy v1.17.0の `binomtest` と照合し一致した。これは指定された確率的な方針の追加整理であり、人間・完全最善対戦の差を検定したものではない。

旧方式はxorshiftの線形性から、2人の同じ呼出番号の出力のXORがseedに依存しない。128 seed・各5回の出力で、旧方式は各回1種類のXOR値しかなく、R2は各回128種類だった。[点検結果](../tools/v080-balance/results/sampler-audit.json)。R2は異なる主体・呼出番号を分けたSHA-256カウンター方式を使用する。乱数の数学的独立性の証明は主張しない。

旧方式の本日初回は自己対戦search4で先攻43.3%、修正後は57.2%だった。方法上の違いが先後評価へ大きく影響するため、初回と旧3個投入案の勝率を今回の判断に混ぜない。旧数値・ソース・署名は保持し、方法の注記を追加した。盤上の会計・種まき循環・棋譜照合は別の検証として扱う。他の過去研究系列まで点検済みとはしない。

R2の準備検証は597候補遷移、1,859南北交換局面、36棋譜再構築、48探索照合、初手の乱数消費40局。正式記録では全ブロックの署名・ソース・seed・集計を照合し、62局を再実行・再構築、851南北交換局面を照合した。停止2局も再構築した。初手・画面AI・乱数点検・統計補記は、正式対局後の追加診断として保存している。

数値表と原集計を生成する `report.py` の後に、本書の判断・保守区間・追加診断の解説を編集した。再生成時はこの追記を保持する。元の集約JSONと原記録アーカイブは改変していない。

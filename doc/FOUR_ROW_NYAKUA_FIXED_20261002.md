# 前列・後列の復活とNYAKUA仕様の固定

2026年10月2日。ユーザー指示により、試作v0.6.1からv0.7.0へ変更する。変更前はmain `d24bc51ce06841adca32c5b410b739e8cfaeacdb`。

## 採用した条件

| 項目 | 変更前v0.6.1 | 現行v0.7.0 |
|---|---|---|
| 各人の盤 | 前列8穴のみ | 前列8穴・後列8穴 |
| 両者の盤 | 2列16穴 | 4列32穴 |
| 種まき | 端で折り返し | 自分の前列・後列を循環 |
| 初期前列 | 6・2・2 | 同じ |
| 初期後列 | なし | 全穴空 |
| 初期ハンド | 各12個 | 各22個 |
| 総KETE | 44個 | 64個 |
| NYAKUA | NAMUAで捕獲2回以上、相手ハンド2個以上なら1個奪取 | 同じ条件を固定 |
| 最後の1個保護 | 暫定採用 | 現行仕様として固定 |
| 一穴全投入 | 試用 | 現行仕様として固定 |

相手ハンド0なら、残り全部を通常の合法な開始穴へ一度に投入する。捕獲義務、全捕獲、NYUMBA、連続種まきを維持する。両者のハンドが0になるまで共通NAMUA、以後共通MTAJI。片側だけ先にMTAJIへ入る規則やNYUMBA残数による部分捕獲上限は採用しない。

通常の初期局面からは最後の1個保護と全投入によりパスは生じない。互換性のため人工局面のハンド0側パスは保持する。勝利条件は相手の前列全空または合法手なしで、後列の残数だけでは前列全空による敗北を防げない。

## 実装

保存済みの `bulk-engine.js` に前後列・循環・ハンド22個・全投入の処理があるため、そのルール本体を変更せず `four-row-engine.js` で現行仕様の定数を固定する。HTMLはこの接続層を読み、`steal.js` は最後の1個保護を有効にする。画面にルール切替設定は置かない。

`engine.js`・`bulk-engine.js`・`bounce-engine.js`・`steal.js` は変更しない。過去の試験は明示したエンジンと発動条件で再現できる。新しい進行確認は現行の `four-row-engine.js` を使用する。

画面を32穴にし、上からNORTH後列、NORTH前列、SOUTH前列、SOUTH後列とする。NAMUAでは前列、MTAJIでは合法な前列・後列を選べる。着手の再生、全投入の表示、簡易コンピューター、対局の取消・再開始も維持する。

棋譜をversion 6、`rulesVersion: "0.7.0"`、`variantRule: "namua-steal-one-protect-last-fixed-pit-bulk-two-row-ring-hand22"` とする。前後列・循環・ハンド22個・総数64個、最後の1個保護・一穴全投入の固定条件を記録する。旧1列盤の棋譜と区別する。棋譜の画面読み込みは未実装。

## 検証

- 新旧のエンジン・ルール・画面を含む30自動テストが通過。
- 前列端から後列へ移る経路、16穴の循環、最後の1個保護、相手ハンド0・1・2・5の奪取条件、全投入1回、共通MTAJI、MTAJIで奪取しない条件を確認。
- 画面のDOM自動テストで、NYAKUAと2個の全投入を含む52手番を終局まで再生。後列からの着手、全32穴の個数、ハンド表示、棋譜の識別情報と再構築、コンピューター着手、取消・再開始が一致。
- 無作為・評価差許容・一手評価・一手応答の各100局、計400局が前列全空か合法手なしで通常終局。負数・総数違反・連続種まき安全上限・400手番打切り・パスは0件。
- 40組の南北交換と40局の棋譜再構築が一致。8,873候補遷移で通常処理・イベント処理・最後のスナップショットが一致。

[確認コード](../tools/four-row-nyakua-check.cjs)と[結果・ソースSHA-256](../tools/four-row-nyakua-results.json)を保存する。この400局は先後均衡の確認ではなく、採用条件の実装・進行確認である。過去の対局数へ合算しない。

## 適用範囲

本変更はユーザーが選んだ実装仕様の反映であり、先後均衡の達成を理由とする採用ではない。直前の後列あり比較でも方針によって先後の偏りが変わった。旧1列盤や最後の1個を奪える旧4列盤の勝率・必勝証明は、現行条件へ引き継がない。

元ゲームの採用基準・保存済みエンジンの実装範囲を引き継ぐ。takasia未実装と連続種まきの安全上限があり、すべての大会・地域規則への完全な準拠や、全局面の停止を証明したものではない。
